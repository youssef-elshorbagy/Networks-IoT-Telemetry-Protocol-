# IoT Telemetry Protocol — Team 38

A custom UDP-based protocol for reporting IoT sensor telemetry (temperature and humidity) from multiple simulated devices to a central server, with support for acknowledgements, sequence tracking, batch transmission, and testing under simulated network impairment (packet loss, delay, jitter, duplication).

Built for a Computer Networks course project. Includes a custom binary packet format, a Python client/server implementation, an automated test harness with 7 network-condition scenarios, and metrics/graph generation from captured traffic.

📽️ **Demo video:** [Watch here](https://drive.google.com/file/d/1ZGdacjdz2DCFYup1epudbYF93Y2JiecW/view?usp=sharing)

## Project Structure

```

├── server.py                  # UDP server: receives, ACKs, and logs telemetry
├── client.py                  # Simulated IoT device client
├── test.py                    # Automated test harness (runs scenarios, collects metrics)
├── device_logs/                # Per-device CSV logs generated by the server
├── pcap_captures/               # Captured network traffic per test run
├── test_graphs/                # Generated metric graphs
├── Ready Tests results/         # Pre-recorded results for each test scenario
├── final_metrics.csv           # Summary metrics across test runs
├── technical report.pdf

├── Mini-RFC draft (sections 1-7) fully updated.pdf
├── Computer_Networks_Proposal.pdf
└── TEAM38.pptx                  # Project presentation slides
```

## Prerequisites

```bash
# Python 3.6+
python3 --version

# Required packages
pip install scapy psutil matplotlib

# For network impairment testing (Linux/WSL2 only)
sudo apt install iproute2
```

> **Note:** Network impairment simulation relies on Linux `netem`, which requires kernel support. WSL1 is not supported. For reliable results, use a native Linux machine or a full Linux VM (WSL2 may have limitations).

## Usage

### 1. Manual Testing

**Terminal 1 — start the server:**
```bash
python3 server.py
```

**Terminal 2 — start one or more clients:**
```bash
# Single client with device ID 0
python3 client.py 0

# Multiple clients (run each in its own terminal)
python3 client.py 1
python3 client.py 2

# Batch transmission mode
python3 client.py 0 batch
```

### 2. Automated Testing

Run the interactive test menu, which drives the server/client(s) through predefined network conditions and collects metrics automatically:

```bash
python3 test.py [num_clients]

# Examples:
python3 test.py          # 1 client (default)
python3 test.py 3        # 3 concurrent clients
```

### 3. Test Scenarios

The test runner includes 7 predefined scenarios:

| # | Scenario | Description |
|---|----------|--------------|
| 1 | Baseline | No network impairment |
| 2 | Packet Loss 5% | Simulates a mildly unreliable network |
| 3 | Packet Loss 50% | Extreme loss conditions |
| 4 | Delay + Jitter (100ms ±10ms) | Variable latency |
| 5 | High Delay + Jitter (2000ms ±5000ms) | Extreme latency conditions |
| 6 | Duplicate 10% | Duplicate packet handling |
| 7 | Baseline Batch Mode (5 packets) | Batch transmission mode |

### 4. Output & Metrics

Each test run automatically generates:
- **Device logs** — `device_logs/*.csv`
- **PCAP captures** — `pcap_captures/*.pcap`
- **Metrics summary** — `final_metrics.csv`
- **Graphs** — `test_graphs/*.png`

Recorded metrics per test:
- `packets_received` (successfully)
- `bytes_per_report`
- `duplicate_rate`
- `sequence_gap_count`
- `cpu_ms_per_report`
